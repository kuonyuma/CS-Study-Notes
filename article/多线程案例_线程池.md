# 1. 场景引入

我是开包子铺的老板。

一开始生意比较冷清，我在店里雇了 3 个人为我打工，就足以维持店里的生意。

后来随着包子越做越好吃，来买包子的人也多了起来，我发现 3 个人无法维持店里的运转了，于是我多招聘了两个服务员。

这样店里的生意又恢复正常了。但经济总有不好的时候，人流减少，又回到了原来 3 个人就足以维持运转的情况。这时候就多出来了两个服务生，他们闲着没事干，只会消耗我发给他们的工资，产出花销但没有回报，这肯定是我不希望看到的。

但仔细一想，如果我现在立刻将他们裁了，我还得赔付一大笔违约金，这太不划算了。

于是我想到了一个聪明的方法：我在店里多招聘两个“临时工/实习生”。反正实习生工资少，被裁掉也不会耗费我很多钱。当包子铺忙碌的时候，这两个实习生就出来帮忙；当店里不忙的时候，超过一定时间我就让他们下班回家。这样我就避免了频繁招聘和解雇正式工，省下了一大笔资源。

在这个场景中，养着这几名固定服务员的“大堂”，就是**线程池**！而顾客排队的等候区，就是**任务队列**。

# 2. 模拟一个简单的线程池

为了更好地理解，我们先自己动手写一个简易版的线程池：



```java
 public MyThreadPool(int count){
        // 这是一个阻塞队列，固定容量为100
        queue = new MyQueue();
        // 手动指定线程池中核心线程的数量
        MyQueueCount = count;
        works = new Thread[MyQueueCount];

        for (int i = 0; i < MyQueueCount; i++) {
            // 创建一个自定义大小的线程数组
            works[i] = new Thread(()->{
                try {
                    while(true){ // 让创建出来的线程固定待机
                        // 有任务就从队列中弹出，没有任务就阻塞等待
                        Runnable task = queue.pop();
                        if(task != null){
                            task.run(); // 执行任务
                        }
                    }
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            },"线程 : " + i);
            works[i].start(); // 启动线程
        }
    }

    // 将任务扔进阻塞队列中
    public void submit(Runnable runnable) throws InterruptedException {
        queue.put(runnable);
    }
```

测试代码如下：


```java
        MyThreadPool pool = new MyThreadPool(2);
        for (int i = 1; i <= 10; i++) {
            final int taskId = i;
            pool.submit(() -> {
                String threadName = Thread.currentThread().getName();
                System.out.println("任务 " + taskId + " 正在执行，线程：" + threadName);
                try {
                    Thread.sleep(1000); // 模拟任务执行耗时
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            });
        }
```

这里我们创建了一个固定线程数量为 2 的线程池。我们往这个线程池中传入了 10 个任务。

由于我们的队列大小为 100，完全装得下这 10 个任务，所以不会出现任务溢出或丢失的情况。这两个核心线程会不断地从队列中获取任务，每个线程获取任务后休眠一秒，接着再去获取下一个任务，直到队列为空。

# 3. 标准库提供的 API

Java 标准库中已经为我们提供了功能强大的线程池实现，它在 `java.util.concurrent` 包中。

我们直接来看 `ThreadPoolExecutor` 最核心、参数最全的构造方法：


```java
 public ThreadPoolExecutor(int corePoolSize, // 1
                              int maximumPoolSize, // 2
                              long keepAliveTime, // 3
                              TimeUnit unit, // 4
                              BlockingQueue<Runnable> workQueue, // 5
                              ThreadFactory threadFactory, // 6
                              RejectedExecutionHandler handler) // 7 
```

这个构造方法有 7 个参数，我们结合包子铺的例子慢慢来看：

### 1. corePoolSize（核心线程数）

**包子铺的正式工**。就算现在没活干，他们也会在店里待着。当有新订单（任务）时，只要正式工还没满，老板就会优先雇佣正式工来处理。

### 2. maximumPoolSize（最大线程数）

**正式工 + 临时工的总人数限制**。如果长凳（`workQueue`）也坐满了，订单还在增加，老板就会开始招募临时工来帮忙。但店里总人数（正式工+临时工）不能超过这个最大值。

### 3 & 4. keepAliveTime & unit（空闲存活时间）

**临时工的解雇观察期**。当生意没那么忙了，临时工会闲下来。如果一个临时工闲着的时间超过了 `keepAliveTime`（单位由 `unit` 决定，如秒、分钟），老板就会把他辞退。正式工默认是不受这个时间影响的，他们会一直留守。

### 5. workQueue（阻塞队列）

**店里的等候位/长凳**。当所有正式工（`corePoolSize`）都在忙时，新来的订单不会立刻找临时工，而是先让客人在长凳上坐着排队。

> **注意：** 任务是先放进队列，队列满了之后，才会去开启临时线程（直至达到最大线程数）。

### 6. ThreadFactory（线程工厂）

**人力资源部（HR）**。负责招人的部门。你可以通过它给每个员工起个好听的名字（比如“包子铺-服务员-01”），方便出问题时记仇找人。

### 7. RejectedExecutionHandler（拒绝策略）

**包子铺的保安**。当正式工全忙、长凳坐满、临时工也招满了，这时候又来了一个新订单，保安就要出面了。Java 默认提供了 4 个保安（策略）：

- **AbortPolicy（默认）**：直接把客人赶走，并大喊大叫（抛出异常）。
    
- **CallerRunsPolicy**：让扔出这个任务的老板自己去送这单（由提交任务的线程自己执行）。
    
- **DiscardOldestPolicy**：把排队排在最前面等得最久的那个客人赶走，让新客人进来。
    
- **DiscardPolicy**：直接把新来的客人拒之门外，且不吵不闹（丢弃任务且不抛出异常）。
    

## 代码演示与执行顺序解析



```java
        // 1. 创建一个容量为 2 的阻塞队列 (长凳只能坐2人)
        BlockingQueue<Runnable> queue = new ArrayBlockingQueue<>(2);
        AtomicInteger threadIndex = new AtomicInteger(1);

        // 2. 自定义 HR (线程工厂)，给员工贴工牌
        ThreadFactory threadFactory = runnable -> {
            Thread thread = new Thread(runnable);
            thread.setName("demo-pool-" + threadIndex.getAndIncrement());
            return thread;
        };

        // 3. 创建线程池
        ThreadPoolExecutor t1 = new ThreadPoolExecutor(
                2,   // 核心线程数 (正式工 2 人)
                4,   // 最大线程数 (总人数最多 4 人，即最多再招 2 个临时工)
                60L, // 临时工摸鱼 60
                TimeUnit.SECONDS, // 秒，就被解雇
                queue, // 等候区
                threadFactory, // HR
                new ThreadPoolExecutor.CallerRunsPolicy() // 保安策略
        );

        // 4. 一次性塞入 6 个任务
        for (int i = 1; i <= 6; i++) {
            final int taskId = i;
            t1.execute(() -> {
                String threadName = Thread.currentThread().getName();
                System.out.println("任务 " + taskId + " 开始执行，所在线程：" + threadName);
                try {
                    TimeUnit.SECONDS.sleep(3);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    System.out.println("任务 " + taskId + " 被中断");
                }
            });
        }
```

**运行结果解析：**

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/ba413dbd87c6477a8321cec4fc1a8c89.png)


这是面试中最容易被考到的**线程池执行顺序**问题。我们一共有 6 个任务，核心线程 2 个，队列容量 2 个，最大线程 4 个。程序启动后，流程如下：

1. **任务 1、任务 2** 进来：此时核心线程没满，马上创建 2 个核心线程（线程1、线程2）开始执行这两个任务。
    
2. **任务 3、任务 4** 进来：核心线程在忙，把它们放进**等候区**（阻塞队列）。此时队列刚好装满（容量为 2）。
    
3. **任务 5、任务 6** 进来：核心线程满，队列也满了！老板马上开始招募**临时工**（创建非核心线程）。于是线程3、线程4被创建，**他们会立刻拿着任务 5 和任务 6 去执行**。
    
4. 所以，第一波同时执行的是：**任务 1、2、5、6**。
    
5. 等这四个任务中的某几个执行完了（3秒后），空闲下来的线程再去队列里把排队等待的**任务 3 和任务 4** 取出来执行。
    

这就是为什么你在控制台看到的输出中，任务 5 和 6 会比任务 3 和 4 先执行的原因！

# 4. 总结

通过包子铺的例子，我们直观地理解了 `ThreadPoolExecutor` 的核心机制。在实际开发和面试中，只需牢记以下 5 个核心结论：

1. **七大参数各司其职**：`corePoolSize`（正式工）决定了常驻线程数；`workQueue`（等候区）用于缓冲突发任务；`maximumPoolSize`（总人数上限）决定了极限承载能力；`keepAliveTime`（解雇倒计时）用来回收闲置的临时工；而 `threadFactory`（HR）和 `handler`（保安）则分别负责线程的创建与任务超载后的善后工作。
3. **任务流转顺序**：很多人误以为任务会先塞满最大线程数然后再去排队，**实际顺序恰恰相反**。正确的执行流转是：**核心线程 -> 阻塞队列 -> 非核心（临时）线程 -> 拒绝策略**。也就是说，队列没满之前，是绝对不会去招临时工（创建非核心线程）的。
4. **四种常见的拒绝策略**：当店里实在塞不下新任务时，Java 提供了 4 名“保安”：
   * `AbortPolicy`（默认）：直接拒绝并抛出异常（大喊大叫）。
   * `CallerRunsPolicy`：把任务退给提交任务的线程去执行（老板自己送）。
   * `DiscardOldestPolicy`：丢弃队列里排队最久的老任务，腾出位置给新任务。
   * `DiscardPolicy`：直接默默丢弃新任务，不抛出异常。
5. **使用线程池的核心价值**：就像包子铺的“正式工+临时工”模式一样，线程池避免了频繁创建和销毁线程带来的庞大系统开销，不仅节约了系统资源，还能显著提高程序的响应速度和稳定性。
