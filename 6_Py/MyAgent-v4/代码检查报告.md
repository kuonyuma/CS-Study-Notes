# MyAgent-v4 代码检查报告

> 检查范围：`Main/main.py`、`swe/agent.py`、`llm/gemini.py`、`llm/client.py`、`memory/memory_manager.py`、`Tools/*`
> 说明：以下按严重程度排序，逐条给出【位置】【现象】【原因】【修复建议】。建议从 P0 开始依次修改。

---

## 🔴 P0 - 阻断运行（不修就跑不起来）

### BUG-1　`generate_content_stream` 传了不存在的 `tools` 参数
- **位置**：`llm/gemini.py` L39-L42
- **现象**：每次调用 `generate` 都会抛 `TypeError`，被底部 `except` 吞掉后直接 `return`，导致 `think()` 拿到的 `result` 永远是 `None`，Agent 只会 yield 一个 `error` 事件。
- **原因**：经实测，SDK 方法签名为
  `generate_content_stream(*, model, contents, config=None)`，**没有 `tools` 参数**。工具必须放进 `GenerateContentConfig`。
- **修复建议**：把 tools 放入 config，删除 `generate_content_stream(... tools=...)`：
  ```python
  config = types.GenerateContentConfig(
      temperature=1.0,
      max_output_tokens=8192,
      system_instruction=system_instruction,
      tools=function_calls,   # ← 移到这里
  )
  response = await client.aio.models.generate_content_stream(
      model=model_name, contents=contents, config=config,
  )
  ```

### BUG-2　注册的工具从未传给模型（工具调用完全失效）
- **位置**：`swe/agent.py` L92-L97（`think()` 调用 `gemini.generate`）
- **现象**：即便修好 BUG-1，`read/write/terminal` 依然不会被调用。`function_calls` 永远为空，Agent 退化为纯聊天。
- **原因**：`think()` 调用 `generate` 时根本没传 `function_calls`；而且全项目没有任何地方把 `self.tools`（Python 函数）转换成 `types.Tool` / function declarations。
- **修复建议**：把注册的函数转换成工具声明后传入。google-genai 支持直接传 Python 可调用对象：
  ```python
  async for event in gemini.generate(
      self.client, self.mode_name,
      contents=self.contents,
      system_instruction=self.system_prompt,
      function_calls=[types.Tool(function_declarations=[...])],  # 或直接传 callables
  ):
  ```
  最简做法：`function_calls=list(self.tools.values())`，让 SDK 自动根据函数签名+docstring 生成声明（需确认 SDK 版本支持）。

### BUG-3　`compress_contents` 调用方式全错
- **位置**：`memory/memory_manager.py` L35-L43
- **现象**：一旦启用（目前在 `agent.py` L87 被注释掉），必然报错。
- **原因**：两个错误叠加：
  1. 传了不存在的参数 `use_tools=False`（`generate` 的签名里是 `function_calls`）→ `TypeError`。
  2. `generate` 是 **async generator**，却当成同步对象取 `tmp.text` → 永远拿不到文本。
- **修复建议**：用 `async for` 迭代，从 `end` 事件的 `result.full_text` 取摘要：
  ```python
  tmp_text = "历史摘要提取失败。"
  async for ev in gemini.generate(client=client, model_name=model_name,
                                  contents=query,
                                  system_instruction="..."):
      if ev.type == "end" and ev.result:
          tmp_text = ev.result.full_text
  ```

## 🟠 P1 - 高危（能跑但结果错误）

### BUG-4　模型名疑似无效
- **位置**：`swe/agent.py` L31 `self.mode_name = "gemini-3.6-flash"`
- **现象**：API 大概率返回 404/400。
- **原因**：不存在名为 `gemini-3.6-flash` 的模型。
- **修复建议**：改成有效模型名，如 `gemini-2.0-flash` / `gemini-2.5-flash`。同时属性名拼写建议改为 `model_name`（`mode_name` 易误导）。

### BUG-5　工具错误被伪装成成功，模型无法区分成败
- **位置**：`Tools/read.py`、`Tools/write.py`（返回错误字符串而非抛异常）配合 `swe/agent.py` L73-L78
- **现象**：文件不存在时 `read` 返回 `"错误: 文件未找到:..."`，但 `execute_tool` 不会进 `except`，于是 `status` 仍是 `SUCCESS`。模型收到"成功"却是一段错误文本，无法正确重试。
- **修复建议**：二选一——① 工具内部改为 `raise`，由 `execute_tool` 统一捕获；② 或在 `execute_tool` 里检测返回值是否以"错误"开头来判定 `FAILED`。推荐 ①。

## 🟡 P2 - 中等（健壮性/可维护性）

### BUG-6　`generate` 异常被静默吞掉
- **位置**：`llm/gemini.py` L85-L87
- **现象**：出错时只 `logging.error` 然后 `return`，不 yield `error`/`end` 事件，真正的异常信息对上层不可见，排查困难。
- **修复建议**：`except` 中 `yield stream_event(type="error", text=str(e))` 再 return。

### BUG-7　`full_text` 初始值多了一个空格
- **位置**：`llm/gemini.py` L48 `full_text: str = " "`
- **现象**：每次模型输出/历史记录都被插入一个前导空格。
- **修复建议**：改为 `full_text: str = ""`。

### BUG-8　工具响应 key 名不统一
- **位置**：`swe/agent.py` L68-L78
- **现象**：成功用 `output`，普通失败用 `output`，但"工具未注册"时用 `error_message`。键名不一致，模型解析不稳定。
- **修复建议**：统一为固定字段，例如始终用 `{"status", "output"}`。
